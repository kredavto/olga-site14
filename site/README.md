# OLGA — цифровой интерьерный showroom

Премиальный сайт мебели по индивидуальному проекту: не каталог, а
интерактивный журнал об интерьерах. Тёмный графит, крупная типографика,
очень крупные кадры, кинематографичный motion.

Опирается на `design-system/` в корне репозитория: та же пропорция
**85 / 10 / 5**, шаг сетки 8px, стиль подписей `uppercase +0.14em`,
акцент — тот же охристо-бронзовый, easing и правила `prefers-reduced-motion`.
Здесь эта система развёрнута в тёмную тему (см. `src/styles/tokens.css`).

---

## Быстрый старт

```bash
cd site
npm run setup     # медиа-плейсхолдеры + локальные шрифты + сборка
npm run dev       # http://localhost:8100
```

Отдельно:

```bash
npm run build     # dist/index.html + dist/assets из content/site.json
npm run media     # перегенерировать плейсхолдеры (python3 + numpy + pillow)
npm run fonts     # обновить локальные подмножества шрифтов
```

`dist/` — готовый статический сайт: заливается на любой хостинг или CDN
как есть. Внешних запросов в рантайме нет (шрифты локальные, карта своя).

## Замена контента: всё через `content/site.json`

Структура сайта не зависит от количества элементов. Добавили проект в массив —
он появился в галерее и в фильтрах; добавили материал — вырос мозаичный блок;
добавили этап производства — удлинилась scroll-сцена (её высота считается от
числа слоёв в рантайме). Пересборка — `npm run build`.

| Что меняем | Где | Что происходит |
|---|---|---|
| Проекты | `projects.items[]` | Карточки, фильтры и счётчик пересчитываются |
| Категории | `catalog.items[]` | Новая полноэкранная зона в каталоге |
| Материалы | `materials.items[]` | Плитка мозаики (порядок = раскладка, см. ниже) |
| Отзывы | `testimonials[]` | Слайд в закреплённой сцене |
| Сертификаты | `quality.documents[]` | Карточка + fullscreen-модалка |
| Этапы производства | `production.steps[]` | Слой в scroll-сторителлинге |
| Цены калькулятора | `calculator.steps[].options[]` | `base`, `rate`, коэффициенты `k` |
| Вопросы квиза | `quiz.questions[]` | Шаги и прогресс `01 / 0N` |
| Аннотации в hero | `hero.annotations[]` | Точка `x/y`, подпись `tx/ty`, момент `at` (0…1) |
| Контакты, меню, футер | `contacts`, `nav`, `footer` | Везде сразу |

### Порядок материалов важен
Мозаика в секции «Материалы» задаёт разные форматы по позициям
(1 — вертикальный, 2–3 — широкие, 5–7 — квадраты, 8 — панорама).
Изображения генерируются под эти пропорции — при замене держите тот же
порядок или поправьте `.mats` в `sections.css`.

## Медиа

Все изображения в `dist/media/` — **процедурные плейсхолдеры**, чтобы сайт
можно было смотреть и обсуждать до реальной съёмки. Они не претендуют на
роль финального контента: это тёмные архитектурные сцены пяти типов
(общий план, перспектива, фронтальная стена, гардеробная, макро-деталь)
и восемь макро-текстур материалов.

Замена на реальную съёмку — это правка путей в `site.json`, без изменения
разметки. Рекомендуемые размеры — как у текущих файлов
(hero-кадры 1280×720, каталог 1400×1000, проекты wide 1600×1000 /
tall 900×1350 / detail 900×900, case и CTA 1920×1080).

### Фотографии: удалённый URL + локальный запасной кадр

Любое поле с картинкой в `site.json` принимает либо локальный путь
(`media/...`), либо внешний URL. Внешние подключены к CDN Unsplash —
это разрешено их лицензией и бесплатно для коммерческого использования:

```json
"image": "https://images.unsplash.com/photo-XXXX?auto=format&fit=crop&w=1920&h=1080&q=78",
"fallback": "media/case-01.jpg"
```

`fallback` обязателен для внешних адресов: если картинка не загрузилась
(нет сети, адрес протух), `app.js` молча подставит локальный кадр — вместо
фотографии будет заглушка, но не «битая картинка».

**Перед подключением адреса нужно знать, что на снимке.** Ссылка,
которая просто «живая», ещё ничего не гарантирует: в первой версии так на
сайт мебельного ателье попали кадр из ресторана и особняк у воды. Живой
адрес подтверждает доступность, но не тему — сюжет надо проверять
отдельно (открыть снимок, либо посмотреть alt-текст там, откуда взят адрес).

Сейчас подключены два кадра, у которых сюжет подтверждён по alt-тексту
(«Гостиная до/после подготовки»). Остальные слоты держат процедурные
заглушки: адрес с непроверенным сюжетом на боевой сайт не ставится.

**Чтобы добавить фотографию**, достаточно вставить ссылку в `site.json` и
пересобрать (`npm run build`). Подойдёт любая прямая ссылка на изображение —
Unsplash, Pexels или ваш собственный CDN. Параметры Unsplash (`w`, `h`,
`crop`, `q`) позволяют получить нужное кадрирование без графического редактора.

### Hero: видео на первом экране

Сейчас в hero стоит `media/hero.mp4` — перекодированный `rep6.mp4`: без звука,
с ключевым кадром каждые 0.25 с. Это главное требование к файлу: в исходнике
было 2 ключевых кадра на 8 секунд, и перемотка по нему шла рывками.

```bash
ffmpeg -i исходник.mp4 -an -c:v libx264 -preset slow -crf 22 \
       -g 6 -keyint_min 6 -sc_threshold 0 -movflags +faststart media/hero.mp4

ffmpeg -i исходник.mp4 -an -vf scale=854:-2 -c:v libx264 -preset slow -crf 26 \
       -g 6 -keyint_min 6 -sc_threshold 0 -movflags +faststart media/hero-mobile.mp4
```

Проверить, что ключевых кадров достаточно:

```bash
ffmpeg -skip_frame nokey -i media/hero.mp4 -vsync 0 -f image2 /tmp/k-%03d.jpg
ls /tmp/k-*.jpg | wc -l     # ожидаем длительность × fps / 6
```

`media/hero-NN.jpg` — те же 40 кадров, нарезанные из видео. Они служат
постером и запасным вариантом; если понадобится вернуть скраб по кадрам
(например, на iOS — там перемотка видео работает хуже), достаточно очистить
`hero.video` в `site.json`.

Поля конфига:

```json
"hero": {
  "video": "media/hero.mp4",
  "videoMobile": "media/hero-mobile.mp4",
  "poster": "https://…",
  "posterFallback": "media/hero-00.jpg",
  "playback": "once",
  "frames": { "pattern": "media/hero-{i}.jpg", "count": 40, "pad": 2 }
}
```

`playback` задаёт режим первого экрана:

| значение | что происходит | высота секции |
|---|---|---|
| `once` (сейчас) | при загрузке видна фотография-постер, через 1.4 с поверх неё проявляется ролик и играет один раз, кадр в конце остаётся | 1 экран |
| `loop` | то же, но ролик идёт по кругу | 1 экран |
| `scrub` | ролик перематывается скроллом | 4.6 экрана |

В режимах `once`/`loop` видео лежит отдельным слоем поверх постера и открывается
по событию `playing` — не «на всякий случай», иначе поверх фотографии появилось бы
пустое место. Ролик ставится на паузу, когда экран уходит из вида, и после
окончания не перезапускается.

**Автозапуск нельзя считать гарантированным.** Его запрещают политика браузера,
режим энергосбережения и `prefers-reduced-motion`; Safari к тому же не догружает
медиа заранее, поэтому ждать `canplay` перед `play()` нельзя — событие может не
прийти вовсе. Поэтому запуск устроен так:

1. через `INTRO` (1.4 с) вызывается `play()` без ожидания готовности;
2. если он отклонён — над фотографией появляется кнопка «Смотреть ролик»;
3. параллельно ролик стартует от первого же действия пользователя
   (клик, клавиша, касание, колесо);
4. при `prefers-reduced-motion` ролик сам не стартует, но кнопка есть сразу.

Из-за этого первый экран не может молча остаться без видео: либо оно играет,
либо видна кнопка запуска.

Кнопка — сосед `.hero__stage`, а не его потомок: у стейджа свой `z-index: 0`,
внутри него кнопка оказывалась под заголовком и не принимала клик.

`posterFallback` — локальный кадр на случай, если удалённый постер не открылся.

**Аннотации привязаны к таймингу ролика.** `at` — доля длительности, равная
`секунда / длительность` (в режиме `scrub` — та же доля, но по прокрутке); `x`,`y` — точка на экране в процентах, `tx`,`ty` —
подпись. Координаты снимаются с реальных кадров, а не назначаются на глаз:
`object-fit: cover` обрезает видео по бокам, поэтому точки держат подальше
от краёв. Текущая раскладка — 1 c фурнитура, 2 c подсветка, 3 c эмаль,
5 c геометрия, 7.5 c шпон.

**Локальная проверка требует сервера с поддержкой Range.** `python -m http.server`
игнорирует Range-запросы, и видео в браузере не перематывается вообще —
выглядит как поломка скраба, хотя на Vercel всё работает.

### Видео в кейсе проекта

`caseStudy` принимает те же поля, что и hero: `video`, `videoMobile`, `poster`.
Если `video` пуст, секция рендерит `image` — переключение обратно на фотографию
это одно поле.

Здесь видео **не скрабится**: у секции своя scroll-анимация (кадр растёт с 70%
до 100% экрана, параллельно считаются цифры), и второй скраб спорил бы с ней.
Ролик просто идёт по кругу и останавливается, когда секция уходит с экрана —
иначе декодер работает вхолостую всю страницу. При `prefers-reduced-motion`
остаётся постер.

Частые ключевые кадры тут не нужны (перемотки нет), поэтому кодируется проще
и легче hero:

```bash
ffmpeg -i исходник.mp4 -an -vf "scale=1920:-2:flags=lanczos,unsharp=5:5:0.9:5:5:0" \
       -c:v libx264 -preset slow -crf 21 -movflags +faststart media/case-01.mp4
```

## Подключение CMS / админ-панели

`content/site.json` — это и есть контент-модель. Варианты:

1. **Headless CMS** (Strapi, Directus, Sanity, Netlify CMS). Поля повторяют
   ключи JSON; вебхук на публикацию дёргает `node build.mjs` и деплой.
   Для Netlify CMS достаточно описать коллекции в `admin/config.yml` —
   файл-бэкенд уже совместим по структуре.
2. **Git-based** (Decap/Tina): редактор правит `content/site.json` в репозитории,
   CI собирает `dist/`.
3. **Свой бэкенд**: отдавайте тот же JSON по API и вызывайте `build.mjs`
   в момент публикации; фронт остаётся статикой.

Медиа загружаются в `dist/media/` (или в S3/CDN — тогда в `site.json`
указываются абсолютные URL, код это уже поддерживает).

### Приём заявок
Форма (`src/js/app.js`, обработчик `.sheet__form` submit) сейчас показывает
экран успеха без отправки — это единственная точка интеграции. Подставьте
свой endpoint:

```js
await fetch('/api/lead', { method: 'POST', body: new FormData(form) });
```

Поле `context` уже передаёт, из какого блока пришла заявка
(hero / calculator / quiz / cta-measure / contacts / dock), а из квиза —
выбранные ответы.

## Motion

Один `requestAnimationFrame`-цикл обслуживает все scroll-сцены; отдельные
слушатели скролла не плодятся. Реализовано:

scroll-driven video (hero) · pinned horizontal scroll (преимущества) ·
смена пространств (каталог) · parallax (галерея, CTA) · split-text reveal ·
clip-path reveal · staggered reveal (фильтры) · зум кадра + счётчики (case study) ·
масочная смена слоёв (производство) · crossfade-слайды (отзывы) ·
mouse tracking (материалы) · magnetic buttons · кастомный курсор ·
animated number counter (калькулятор) · горизонтальный timeline.

Всё это выключается при `prefers-reduced-motion: reduce` — контент остаётся
полностью доступным (проверено: ни один элемент не остаётся невидимым).

### Две вещи, о которые легко споткнуться
- **`clip-path` схлопывает бокс**, и `IntersectionObserver` перестаёт видеть
  элемент. Поэтому обрезается вложенный `.clip-target`, а наблюдается родитель.
- **`position: absolute` у псевдоэлемента внутри горизонтального скролла**
  цепляется к ближайшему позиционированному предку и растягивает страницу.
  У `.tl__i` поэтому явный `position: relative`.

## Доступность и производительность

- Семантические landmark'и, `aria-*` на интерактиве, видимый фокус, skip-link.
- Модалки закрываются по `Esc` и клику по подложке, фокус возвращается.
- Хотспоты и мозаика материалов имеют не-hover альтернативу на тач-устройствах;
  горизонтальные сцены на мобильном становятся вертикальными.
- Шрифты локальные (latin + cyrillic, 16 файлов ≈ 528 КБ), `font-display: swap`,
  первые два preload'ятся.
- Все изображения `loading="lazy"` кроме первого кадра hero (`preload`).
- HTML ≈ 58 КБ, CSS + JS без зависимостей и без внешних запросов.
